# 岔路 · Side Branch 使用指南

从对话的任意历史节点**继续追问**，或者**改写某一轮的提问后重来**。分支在右侧栏打开，主会话保持原样，你可以左右对照着看。

分支是一个完整的 DSH 会话：可以切换模型、调整权限、改文件、处理审批，和主会话的用法一样。

## 1. 安装与启用

1. 在 DSH 左侧点 **插件**。
2. 点 **添加插件** 旁的下拉箭头，选 **安装第三方插件**。
3. 在“包名或地址”中填入 `side-branch` 目录的绝对路径，例如：

   ```text
   /Users/<你的用户名>/dsh-plugin/side-branch     # macOS
   E:\dsh-plugin\side-branch                      # Windows
   ```

   macOS 可在终端进入该目录执行 `pwd` 得到路径，或把 Finder 中的文件夹拖进终端窗口。

4. 点 **安装**，等待完成。
5. 在“已安装插件”中找到 **岔路 · Side Branch**，打开启用开关。

启用后检查两处：

- 已完成回复下方的操作行出现 **侧栏分支** 和 **编辑本轮提问** 两个按钮；
- 右侧栏引导页出现 **岔路 · 侧栏分支** 卡片。

如果安装结果提示需要重启，按提示安排即可，插件本身不会重启 DSH。

卸载：在插件页移除 **岔路 · Side Branch**。已经创建的分支会话不会被删除，仍可在会话列表中打开。

## 2. 两种用法

| 用法 | 按钮 | 分支里有什么 | 适合 |
|---|---|---|---|
| **续问** | 侧栏分支 | 第 1 轮到第 N 轮（含第 N 轮的回答） | 针对某一轮追问细节；从某个节点换个思路继续 |
| **改写提问** | 编辑本轮提问 | 第 1 轮到第 K−1 轮，再加你改写后的第 K 轮提问 | 发现第 K 轮问错了，想改了问题重来 |

举例：主会话已经聊到第 5 轮，你发现第 2 轮的问题问错了。

- 在第 2 轮回复下方点 **编辑本轮提问**；
- 右侧栏打开新分支，输入框里已经填好第 2 轮的原问题；
- 改成正确的问题后发送。AI 只看到第 1 轮和你的新问题，第 2–5 轮不会带进来。

主会话的 5 轮记录始终不变。

## 3. 入口一：回复下方的按钮

每个已完成轮次的回复下方有一排操作按钮（复制、好的回答、有问题的回答等）。插件在这一排加入两个文字按钮：

```text
[复制] [好的回答] [有问题的回答]  侧栏分支  编辑本轮提问  [在新对话中分支] [用量]
                                  └─ 本插件 ─┘           └─ DSH 自带 ─┘
```

- **最新一轮**的按钮始终显示；**更早的轮次**需要把鼠标移到回复上才会出现。
- 鼠标悬停在按钮上会提示具体操作，例如“分支来自第 3 轮之后”“正在编辑第 2 轮提问”。
- 点击后，分支在**右侧栏**打开，主视图不动。

注意区分 DSH 自带的 **在新对话中分支**（图标按钮）：它会新建会话并**切走主视图**。插件的按钮则把分支放在侧栏里，并且支持改写提问。

### 按钮什么时候是灰的

| 情况 | 侧栏分支 | 编辑本轮提问 |
|---|---|---|
| 这一轮还在运行 | 不可用 | 不可用 |
| 最终回复之后还有工具调用或报错 | 不可用 | 可用 |
| 这一轮没有你发的提问（例如系统唤醒的轮次） | 可用 | 不可用 |

某一轮回答失败、回复下方没有操作行时，可以改用右侧栏选择器（见下一节）来改写这一轮的提问。

## 4. 入口二：右侧栏选择器

适合长会话，或者想先看清每一轮再决定从哪里开始。

1. 点会话右上角的 **打开右侧边栏**；如果右侧栏已经有其他标签，点标签栏上的 **+**。
2. 在引导页点 **岔路 · 侧栏分支**。
3. 选择模式：**从本轮之后续问** 或 **编辑本轮提问**。
4. 在轮次列表中点选一轮。每一项显示轮次号、提问开头和回答开头；不能选的轮次是灰的，并注明原因。
   - 轮次超过 50 个时，顶部会出现“筛选提问或回答”输入框。
5. 下方会显示这次分支的信息：
   - 切点之后还有几轮、可能改过哪些文件（详见[第 7 节](#7-重要文件不会回滚)）；
   - 编辑模式下可以展开 **查看原提问**；
   - 原提问带有附件时，会提示你重新添加。
6. 点 **创建并在侧栏打开**。

## 5. 在分支里工作

### 分支标签的样子

```text
┌────────────────────────────────────────────┐
│ [改第3轮] [自第2轮] [+]                     │  ← 每个分支一个标签
├────────────────────────────────────────────┤
│ 正在编辑第 3 轮提问  [在主视图打开] [关闭分支标签] │
│ 保留第 1–2 轮；不继承第 3–5 轮                │
│ 切点之后源会话还有 3 轮；当前工作区文件没有回滚 │
│   ▸ 查看 3 个可能已变动的文件                 │
│   ▸ 查看原提问                               │
├────────────────────────────────────────────┤
│  （分支对话：与主会话完全相同的界面）          │
│                                            │
│ ┌ 输入框（已预填原问题）────────────────┐   │
│ │ 用 Go 实现一个限流器|                 │   │
│ │ [+] 访问模式   模型选择          [发送] │   │
│ └───────────────────────────────────────┘   │
└────────────────────────────────────────────┘
```

- **标签标题**：“自第 N 轮”表示续问，“改第 K 轮”表示改写提问。
- **顶部说明**会随状态变化：改写模式在发送前显示“正在编辑第 K 轮提问”，发送后显示“改第 K 轮”；续问显示“分支来自第 N 轮之后”。
- **下方是 DSH 原生对话界面**：流式输出、工具卡片、文件改动卡片、审批卡片、AI 提问卡片等都和主会话一样。

### 改写提问

- 原问题的**完整文本**已经填进输入框，直接修改后发送即可。
- 输入框里已有你自己的草稿时，插件不会覆盖。
- 原问题里的图片和文件**不会自动带上**，需要在输入框里重新添加。
- 发送之前可以随时展开 **查看原提问** 对照。

### 模型与权限

- 分支创建时，**模型、思考强度和权限都沿用源会话当前的设置**。
- 想换模型或权限，直接用分支输入框下方的**模型选择**和**访问模式**按钮，只影响这个分支。
- 提醒：DSH 原生的模型选择器在切换模型时，会同时改变“新建会话的默认模型”。这是 DSH 自身的行为。

### 其他操作

- **在主视图打开**：把分支切到中间的主视图，用大窗口继续。
- **多个分支**：同一会话可以同时开多个分支标签，互不影响。
- **分支再分支**：分支本身是普通会话，它的回复下方同样有这两个按钮。
- **会话列表**：分支会出现在左侧会话列表中，紧挨着源会话，名称形如：
  - `原会话标题 · 自第 3 轮`
  - `原会话标题 · 改第 2 轮`

  名称可以照常重命名。

### AI 在分支里知道什么

发送第一条消息时，插件会附带一段简短说明，告诉 AI：

- 这个会话分支自源会话第几轮，之后还有几轮它看不到；
- 切点之后哪些文件可能被改过，修改前要重新读取；
- 源会话可能还在同一个工作区工作。

这段说明只包含轮数和文件路径，**不会**把切点之后的对话内容透露给 AI。

## 6. 关闭、保留与归档

分支是持久会话：收起侧栏、切换标签、刷新页面或重启 DSH，分支都还在。

### 用“关闭分支标签”按钮（推荐）

| 分支状态 | 结果 |
|---|---|
| 还没发过消息 | 自动归档，标签关闭 |
| 已有对话 | 询问“保留还是归档此分支？”，可选 **保留**（默认）、**归档** 或 **取消**；勾选 **记住我的选择** 后以后不再询问 |
| 正在运行 | 可以保留；归档前需要先在分支里点停止 |

### 用标签上的 ×

标签会立刻关闭，**分支会话保留**。插件随后在后台判断：

- 没有消息 → 自动归档；
- 有消息 → 按你记住的选择处理，没有记住选择时，右侧栏会打开岔路引导页，在 **待处理的分支** 中让你选择保留或归档；
- 如果你已经切到了别的会话，插件不会打扰你，下次打开 **岔路 · 侧栏分支** 引导页时再处理。

在“待处理的分支”中还可以点 **重新打开** 恢复标签，或点 **清除记住的关闭选择** 恢复每次询问。

### 找回已归档的分支

在左侧会话列表的 **视图选项** 中选择显示已归档会话，找到该分支后取消归档即可。插件从不删除会话。

关闭标签**不会停止**正在运行的分支任务。

## 7. 重要：文件不会回滚

**分支只回退了对话历史，磁盘上的文件不会回到过去。** 分支和主会话使用同一个工作目录。

例如：你在第 2 轮让 AI 写了 Python 代码，第 3–5 轮又改了好几次。现在改写第 2 轮让它改用 Go，这时：

- AI 只记得第 1 轮；
- 但第 2–5 轮写的 Python 文件**仍然在磁盘上**。

插件的应对：

- 分支顶部显示 **“切点之后源会话还有 X 轮；当前工作区文件没有回滚”**，展开可查看可能被改过的文件；
- 首条消息附带的说明会列出这些文件，要求 AI 修改前先重新读取；
- DSH 的文件工具本身要求“先读后改”，如果文件被另一边改过，AI 的编辑会被拒绝并要求重新读取。

文件清单的局限：清单来自 DSH 的改动记录和工具调用记录，**通过 shell 命令或外部程序改的文件可能不在清单里**，这时会提示“可能存在未列出的文件改动”。

**建议：**

1. 改写较早的轮次前，先用 Git 提交或暂存当前改动，方便对比和回退。
2. 在改写后的提问里直接说明你的期望，例如“请先删除之前生成的 `limiter.py`，再用 Go 重写”。
3. 主会话和分支同时运行时，避免让两边改同一个文件。两边都在运行时，分支顶部会显示提醒。

## 8. 常见场景

### 问错了，改了重来

在问错那一轮的回复下点 **编辑本轮提问** → 在输入框里修改 → 发送。

### 针对较早的某一轮追问

在那一轮的回复下点 **侧栏分支** → 直接提问。后面几十轮的调试内容不会带进来，回答更聚焦，消耗的 token 也更少。

### 换个模型试另一种方案

在某一轮后点 **侧栏分支** → 在分支输入框下方切换模型 → 提问。两种方案在左右两栏对照。换模型后通常无法复用原模型的缓存，计费以提供方为准。

### 主会话在跑长任务，想顺便问个问题

点最新一轮的 **侧栏分支** → 在侧栏提问，不打断主会话。只问一句、不打算保留的问题，也可以用 side-chat 插件。

### 想把分支作为新的主线

点分支顶部的 **在主视图打开**，之后就在主视图继续。需要的话，可以把原会话归档。

## 9. 出错时怎么办

| 提示 | 含义 | 处理 |
|---|---|---|
| 操作失败 + **重试** | 网络或临时错误 | 点重试。重试会继续完成**同一个分支**，不会重复创建 |
| **检查会话列表后另建分支** | 上次创建的结果不确定，或那个分支已经收到了输入 | 先在会话列表里看看分支是否已存在；确认后点此按钮新建。原会话及已有分支都会保留 |
| 当前 DSH 缺少原生会话嵌入或草稿接口 | 当前 DSH 版本不兼容 | 插件按 DSH 0.2.1-rc.2 开发，升级 DSH 后需重新验证兼容性 |
| 需要迁移 / Open the source in DSH to migrate it | 源会话的存储格式较旧 | 先在主视图打开一次源会话，再创建分支 |
| 分支尚未完成初始化，暂不能发送消息 | 创建过程中断 | 回到原来的按钮点重试 |

## 10. 常见问题

**分支会出现在会话列表里吗？**
会。分支是正式会话，排在源会话旁边。不想保留的可以归档。

**和 side-chat（侧边会话）有什么区别？**

| | side-chat | 岔路 |
|---|---|---|
| 起点 | 只能从最新一轮 | 任意已完成轮次 |
| 改写历史提问 | 不支持 | 支持 |
| 模型、权限、审批、附件 | 能力有限 | 和主会话完全一样 |
| 关闭后 | 销毁 | 保留，可归档、可找回 |
| 会话列表 | 不显示 | 显示 |

**和 DSH 自带的“在新对话中分支”有什么区别？**
自带按钮只能从这一轮之后分支，而且会切走主视图。岔路在侧栏打开，主视图不动，还能改写提问。

**重启 DSH 后分支还在吗？**
在。重新打开源会话，右侧栏的分支标签会恢复。

**改写第 1 轮会怎样？**
会新建一个没有历史的会话，工作目录、模型和权限与源会话相同。这种分支在 DSH 原生的血缘信息里没有“父会话”，来源由插件自己记录。

**分支能继承计划模式、目标（/goal）吗？**
分支继承切点那一刻的状态。按 DSH 的规则，进行中的目标在分支里不会自动继续，需要时手动恢复。

**子代理的会话能作为源吗？**
不能，只支持普通会话。分支本身可以作为源继续分支。

**卸载插件后分支怎么办？**
分支会话都保留在会话列表中，可以照常打开和使用，只是侧栏的岔路功能不再可用。

## 版本说明

本指南对应 **岔路 · Side Branch 0.1.0**，适用于 DSH 0.2.1-rc.2 Desktop。

功能已通过单元测试和基于真实 DSH 服务的隔离集成测试；在实际桌面页面中的排版和点击还没有经过完整的人工验收。如果你看到的按钮位置或文字与本文不一致，以实际界面为准，并请反馈。
