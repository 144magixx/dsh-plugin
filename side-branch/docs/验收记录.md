# 岔路 · Side Branch 0.1.0 · 验证记录

验证日期：2026-10-24。目标：当前安装的 DSH `0.2.1-rc.2`；执行器为随 DSH 提供的 Node `v24.21.0`。

## 对现有运行环境的影响

- 当前 DSH Desktop 保持运行；本次没有关闭、重启或刷新它。
- 未修改当前 profile、安装目录、模型配置或其他任务会话。
- 未安装插件到活跃 profile，未另起 Web 服务器。
- 测试仅从安装包提取依赖到项目目录。所有测试会话、JSONL、存储记录都位于项目的隔离测试目录。
- 集成测试 worker 使用离线保护，拒绝网络连接、监听端口及子进程。测试模型是进程内固定响应适配器，不读取凭据或调用真实模型 API。

## 已验证内容

| 范围 | 验证方式与结果 |
|---|---|
| 编辑历史提问 | 原生 SessionController fork 与 AgentLoop：保留前轮历史，修改后的提问进入新请求；旧提问、后续回答及唯一口令不进入分支模型请求 |
| 首轮编辑 | 创建空历史原生会话；显式归属源工作区，并排在源会话前面 |
| 源会话保护 | 分支创建、提问、归档期间，源日志逐字节一致；源正在运行时仍保持运行，源在冷态时不被激活 |
| 队列隔离 | 原会话提前排队的未来问题即使位于切点之前，也只在新分支里被清理，不会被当作新任务执行 |
| 模型继承 | 分支使用当前源模型及思考强度；初始化不保存全局默认模型；默认思考强度与显式选择按原生语义区分 |
| 权限继承 | 保留当前沙箱、审批策略及真实预设身份；自定义权限不会误继承历史 Auto 身份 |
| 当前目录 | 保留原项目工作区归属，继承源会话当前目录；真实 WorkingDirectory 服务提供的模型上下文匹配该目录 |
| 持久化与重启恢复 | 关闭隔离 Host 后用全新 Context 重新打开：原生会话、插件来源记录、模型及权限可恢复 |
| 说明去重 | 未提交就重启不会丢说明；首次实际模型准入时加入，并在多次提问后只存在一条分支自有说明 |
| 初始化失败重试 | 模拟原生重命名失败，再关闭并重建 Host；重试恢复同一个 child/requestId，不再次 fork，成功后撤销插件归档 |
| 关闭行为 | 无消息且无活跃工作的分支可归档；有已接受输入则不静默归档；运行中关闭不取消工作 |
| 客户端接口 | 使用安装包中的真实 ClientModuleSystem、React 18.3.1、SlotRegistry 与 Conversation，验证原生嵌入工厂及 session 作用域注册 |
| 原生草稿 | 用真实输入框草稿引擎预填完整原文，重复初始化保留用户已改内容 |
| 客户端恢复 | 测试请求 ID 去重、资源释放、错误帧、已提交/排队输入不重复预填、标签关闭恢复和跨会话迟到结果处理 |
| 发行形式 | 客户端为 DSH 经典脚本 ModuleLoader 格式；Host 为 ESM；包包含中英文元数据和原创 SVG 图标 |

最终单元套件：**58 项通过，0 失败**，覆盖历史计算、配置语义、服务故障恢复、首次准入、客户端行为及发行清单。真实运行时集成套件：**11 项通过，0 失败**；最后一次客户端改动后，又单独复跑并通过了真实客户端加载器/原生 Conversation 集成测试。所有交付 JavaScript 均通过语法检查。

## 尚未验证的部分

以下不能仅从测试通过推断成功，需未来安装后的人工页面验收：

- 当前 Desktop 页面中的实际排版、宽度、焦点、滚动与点击响应。
- 页面上真实显示和回答审批、AI 提问、计划审阅卡片的完整交互。
- 实际侧栏布局在浏览器刷新及 Desktop 重启后的恢复；本次测试的是插件来源记录、原生会话恢复与客户端接口。
- 真实文件沙箱对 `write` / `edit` 的执行拦截；测试验证权限事件及投影，没有调用真实执行工具。
- 真实 HTTP/IPC 传输的鉴权握手；插件路由通过原生已认证连接注册，测试替身不实现网络认证。
- 与当前已安装 side-chat 同时运行的真实页面验收；离线验证了共享原生 keyed-slot 注册互不覆盖。
- 1000 轮会话的完整端到端加载性能、真实提供方缓存或计费。
