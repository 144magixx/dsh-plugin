## 1. 背景

### 1.1 现状

| 能力 | 来源 | 选择轮次 | 编辑历史提问 | 主视图跳走 | 进会话列表 | 与主会话并排 | 能力与主会话对等 |
|---|---|---|---|---|---|---|---|
| 每轮回复下方的“分支”按钮 | 内置 `dsh-client-ui-chat` | 可以（在该轮之后） | **不能** | 会 | 会 | 否 | 是（本身就是普通会话） |
| 会话行菜单 “Fork” | 内置 `dsh-client-ui-workspace` | 否（固定最新） | 不能 | 不会 | 会 | 否 | 是 |
| 侧边会话 tab | `@flyer103/dsh-side-chat` | 否（固定最新） | 不能 | 不会 | 不会 | 是 | **否**：没有模型选择、tab 内不显示审批、不支持附件和命令、关掉即销毁 |

### 1.2 问题

1. **改不了历史提问**：用户在第 5 轮发现第 2 轮问错了，DSH 没有“编辑第 2 轮提问并从那里重来”的手段，只能新开会话重新铺垫上下文，或者在后面的轮次里纠正（错误的上下文仍然留着）。
2. **分支要么太重，要么太弱**：内置分支会把主视图切走；side-chat 虽然在侧栏，但能力缩水，也不能选轮次。

## 2. 评估

### 2.1 新需求一：编辑历史提问

- **合理性：高。** “编辑并重新提交”是主流对话产品的标准交互。DSH 的会话日志只追加，没有会话内分支树（`dsh-session` README 把“基于分支会话的条目树”列为延期项），所以只能用 **fork 实现**：分支 = 第 1 至第 K−1 轮 + 修改后的第 K 轮提问。主会话保持原样，这是**非破坏性**的，比原地改写更安全。
- **必要性：高于“选轮次续问”。** 选轮次续问还可以用内置“分支”按钮凑合；编辑历史提问，DSH 目前完全没有替代手段。
- **可行性：可行。** 官方 fork 接受任意切点（`atSeq`）；`turnOutline` 提供每轮 `turn/start` 的 seq，可以据此算出“第 K 轮输入之前”的切点。
- **体验限制**：用户提问气泡**没有公开的扩展点**（`dsh-client-ui-chat` 中用户气泡的操作行只有复制和时间，不接收插件条目），所以“编辑”入口不能直接放在第 K 轮的问题气泡上，只能放在第 K 轮回复下方的操作行，以及侧栏的轮次选择器里。见 FR-2 和决策 D5。

### 2.2 新需求二：与主会话同等公民（有编辑权限、能选模型）

- **合理性：高。** 用户在分支里要做真实工作，不只是问答。
- **它推翻了 v0.1 的三项设定**：临时会话、不进会话列表、历史锚点默认只读。
- **实现路线的结论（详见第 10 节）**：如果走 side-chat 路线（自建隐藏 agent 并自绘界面），模型选择、权限、审批、AI 提问、附件、命令、持久化、重启恢复都要逐项重做，而且永远追不上主会话。**推荐走原生会话路线**：
  - 用官方 `ctx.sessions.fork({ sessionId, atSeq })` 创建一个真正的会话；
  - 在右侧栏 tab 里嵌入**原生对话组件**，包括完整输入框。

  DSH 已有先例：`dsh-client-ui-subagent` 就是在右栏 tab 里通过共享的 `conversation.content` 组件渲染子代理对话（含输入框和停止按钮）。嵌入版本走的是与主会话相同的输入框链路（`conversation.composer` → `conversation.composer.bar` + `conversation.input.dock`）。这样同等公民的能力**天然具备**。

  代价：分支会出现在会话列表里（用归档缓解，见 FR-27）；依赖一个内部组件插槽（见风险 R4，需要原型验证）。

### 2.3 风险升级：工作区漂移成为首要风险

“编辑第 K 轮 + 有写权限 + 与主会话共用同一个工作区”组合在一起，会出现这种情况：**用户想重做第 2 轮，但第 2–5 轮已经写到磁盘上的代码还在。**分支里的模型只“记得”第 1 轮，看到的文件却是第 5 轮之后的样子。这是用户最容易误解的地方，也是最可能造成损失的地方。

**现有安全网：**

- `dsh-fs-observation-policy` 的“编辑前必须读取”记录按会话保存在内存里，**fork 出的会话不继承**。所以分支在用 `write` / `edit` 改动任何已有文件前都必须重新读取；文件被另一方改过后，分支的编辑会以 `FS_STALE_VERSION` 失败并要求重读。
- 这道安全网**不覆盖 shell 命令**造成的改动。

**本插件的缓解手段**：漂移横幅（FR-9）、给模型的分支说明（FR-23）、并发提示（FR-30）。

**根治手段**：工作区隔离，列为 P2（FR-33）。`dsh-workspace-changes` 会在每轮 `turn/start` 时给工作树拍 git 快照（包含未提交改动），“第 K 轮开始前的文件状态”是存在的。但快照只保存在 Host 进程内存里，没有公开读取接口，需要单独研究。

### 2.4 结论

两项新需求都**合理且必要**，其中“编辑历史提问”是本插件相对 DSH 现有能力最大的增量。

推荐的产品定位与 side-chat 区分开：**side-chat 负责临时、轻量的问答；本插件负责真正的分支：可以选起点、可以改历史提问、能力与主会话完全一致。**

实现上推荐原生会话路线，开工前先做 1–2 天的技术验证（M0）。

> 需求理解确认：原话“第 2 轮发了个问题，到第 5 轮发现第一轮问错了”，按“第 2 轮问错了”理解，即分支 = 第 1 轮 + 修改后的第 2 轮提问。

## 3. 目标与非目标

### 3.1 目标

- **G1 两种起点**：
  - 从任意已完成轮次 N **之后**继续（续问）；
  - **编辑**任意轮次 K 的提问并从那里重来（分支 = 第 1 至 K−1 轮 + 新提问）。
- **G2 同等公民**：分支是一个普通 DSH 会话，模型和思考强度、权限预设、审批、AI 提问、附件、@ 引用、斜杠命令、停止、排队、插话、用量统计、持久化、重启恢复都与主会话一致。
- **G3 侧栏并排**：分支默认在右侧栏 tab 中打开，主会话视图、滚动位置和运行状态都不受影响；需要时可以一键在主视图打开。
- **G4 主会话不变**：创建和使用分支都不改变源会话的日志和内容。
- **G5 起点清晰**：用户始终清楚分支从哪一轮来、丢掉了哪些轮次、工作区可能有哪些不一致。

### 3.2 非目标

- 不修改或回滚主会话历史（DSH 日志只追加）。
- MVP 不回滚、也不隔离工作区文件（P2 研究）。
- 不做会话树可视化（P2 可做“本会话的分支列表”）。
- 不在轮次中间任意事件处切开，只在轮次边界切。
- 不提供临时、隐藏、关闭即销毁的模式；这类需求继续使用 side-chat。
- 不支持 CLI/TUI。

## 4. 术语

| 术语 | 含义 |
|---|---|
| 源会话 | 从中分出分支的会话 |
| 续问模式 | 起点 = 第 N 轮**之后**；分支继承第 1 至 N 轮 |
| 编辑模式 | 起点 = 第 K 轮**之前**；分支继承第 1 至 K−1 轮，并以修改后的提问作为分支的第一条消息 |
| 切点 | 继承前缀的最后一个事件 seq（第 6.2 节给出规则） |
| 分支 | 由本插件创建的普通会话，`parentSession` 指向源会话 |
| 漂移 | 切点之后源会话对工作区做出的改动 |

## 5. 用户故事

- **US-1（编辑）**：我在第 2 轮让 AI “用 Python 实现”，做到第 5 轮发现应该用 Go。我想直接改第 2 轮的问题，让 AI 从第 1 轮的上下文重新开始，同时保留原会话以便对照。
- **US-2（续问）**：在 40 轮的长会话里，我想基于第 12 轮的方案追问细节，不带上第 13–40 轮的调试噪音。
- **US-3（同等公民）**：在分支里我要能切换模型（例如用更便宜的模型做探索）、调整权限、真实改文件、在 tab 里处理审批，体验与主会话完全一样。
- **US-4（并排）**：我希望分支在右侧栏打开，与主会话左右对照，不打断主会话正在运行的任务。
- **US-5（漂移知情）**：我编辑第 2 轮时，系统要明确告诉我第 2–5 轮改过哪些文件、这些改动仍在磁盘上。
- **US-6（收尾）**：分支用完关掉 tab 时，我可以选择保留或归档，不让会话列表越来越乱。

## 6. 功能需求

优先级：**P0** = MVP 必须，**P1** = 第二版，**P2** = 远期或待研究。

### 6.1 入口

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-1 | P0 | **续问入口**：在每个已完成轮次回复下方的操作行（与复制、点赞、内置“分支”同一行）加入“侧栏分支”。点击后从该轮之后创建分支，并在右侧栏打开。文案和图标必须与内置“分支”（会切走主视图）区分。内置判定为不可分支的轮次，本入口同样禁用并说明原因。 |
| FR-2 | P0 | **编辑入口**：在同一操作行加入“编辑本轮提问”。由于用户气泡没有公开扩展点，入口放在该轮回复下方，提示文案写明“编辑第 K 轮的提问，并在侧栏从这里重来”。 |
| FR-3 | P0 | **引导页入口**：右侧栏引导页注册“分支”卡片。打开后显示起点选择器（第 6.2 节），由用户选择模式和轮次。 |
| FR-4 | P1 | **嵌套分支**：在侧栏分支内部同样可以使用 FR-1 和 FR-2（分支本身也是普通会话）。 |
| FR-5 | P2 | 快捷键或斜杠命令，例如 `/branch 12`、`/edit 2`。 |

### 6.2 起点选择与切点规则

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-6 | P0 | **两种模式**：续问（第 N 轮之后）和编辑（第 K 轮之前 + 新提问）。 |
| FR-7 | P0 | **轮次列表**：显示轮次号、提问预览（≤50 字）、回答预览（≤120 字）。当前实现由 Host 读取一致的源事件快照并核实结束边界、最终回复和错误状态，只向客户端返回有界预览；`turnOutline` 本身不提供足够的结束与错误状态，因此不能仅凭非空回答预览判定可分支。进行中轮次不可选；续问禁用无最终回复的轮次，编辑模式允许修改已结束失败轮次中的人类提问。超过 50 项时支持关键字过滤。 |
| FR-8 | P0 | **切点规则**：<br>• **续问（第 N 轮）**：精确切在第 N 轮 `turn/end`，不吸收轮末之后可能属于后续工作的上下文；当前模型、权限和目录另行显式继承。<br>• **编辑（第 K 轮）**：切在上一个实际记录轮次的 `turn/end`；不依赖轮次号连续。<br>• **编辑首轮**：新建空历史原生会话，采用源会话当前配置；不复制首轮前可能已接受的原问题队列。原生 `parentSession` 此时为空，来源由插件持久记录。<br>• 切点必须通过 `events[seq].seq === seq` 校验，绝不切在开放轮次中间。 |
| FR-9 | P0 | **漂移横幅**：显示“切点之后源会话还有 X 轮，其中 Y 轮改动了文件”，并可展开文件清单。<br>• 数据优先取 `ctx.workspaceChanges.summary(sessionId, seq)`（仅在源会话存活于本 Host 进程期间可用）。<br>• 取不到时，退而扫描切点之后 `write`、`edit`、`str_replace_editor` 调用的目标路径，并标注“含 shell 命令，可能存在未列出的改动”。<br>• 横幅在起点选择器、编辑流程和分支 tab 顶部都要出现。 |
| FR-10 | P1 | **成本预估**：显示继承前缀的估算 token 数；所选模型与源会话不同时，提示“换模型通常无法复用原模型缓存，实际计费以提供方报告为准”。 |

### 6.3 编辑历史提问

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-11 | P0 | **编辑流程（推荐方案 A，需 M0 验证）**：点击“编辑本轮提问”后：<br>① 按 FR-8 创建分支；<br>② 在右侧栏打开分支 tab；<br>③ 把第 K 轮**首条人类消息的完整原文**（不是预览）预填进分支的**原生输入框**草稿；<br>④ 用户在原生输入框里修改，并可直接使用模型选择、附件、@ 引用、命令；<br>⑤ 按发送即提交。<br>**降级方案 B**：如果无法预填原生草稿，就用插件自己的编辑对话框收集文本、模型和权限，再通过 prompt 接口发送。 |
| FR-12 | P0 | **编辑态提示**：分支在发出首条消息之前，tab 顶部显示“正在编辑第 K 轮提问：分支保留第 1–(K−1) 轮，丢弃第 K–M 轮”，同时显示漂移横幅。 |
| FR-13 | P0 | **不携带的内容**：第 K 轮的插话消息、第 K 轮之后的所有轮次都不进入分支。第 K 轮原提问中的图片和文件附件在 P0 不自动携带，需提示“原提问含 n 个附件，请重新添加”；P1 研究复用原附件对象（附件对象不可变，fork 会话本来就可以共享）。 |
| FR-14 | P0 | **放弃编辑**：首条消息发出之前关闭 tab，视为放弃，按 FR-27 的“无自有消息”规则静默处理。 |
| FR-15 | P1 | **对照**：分支 tab 中提供“查看原提问”，并排或以差异形式对照第 K 轮原文与修改后的提问。 |

### 6.4 同等公民能力

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-16 | P0 | **原生对话渲染**：分支 tab 内嵌原生对话组件，包括流式输出、过程折叠、工具卡片、文件改动卡片、轮次页脚和用量统计，与主会话一致。 |
| FR-17 | P0 | **原生输入框**：模型和思考强度选择、权限预设选择、停止、排队、插话、图片和文件附件、@ 引用、斜杠命令（例如 `/plan`、`/compact`、`/goal`）、技能，与主会话一致。 |
| FR-18 | P0 | **交互请求**：审批请求、AI 向用户提问（`ask_user`）、计划审阅都在分支 tab 内显示并可以作答，绝不出现“等待中但无处作答”。 |
| FR-19 | P0 | **初始配置**：<br>• 模型：默认取源会话**当前**模型和思考强度，而不是官方 fork 使用的全局默认模型（决策 D4）；<br>• 权限：取源会话**当前**的权限预设，绝不沿用继承前缀里的历史权限；<br>• 工作目录和 preset 组合与源会话相同。<br>以上都要在分支首条消息发出之前生效。 |
| FR-20 | P0 | **完整编辑权限**：分支按所选权限预设真实读写工作区，不做额外的只读限制（v0.1 的 D2 作废）。 |
| FR-21 | P0 | **普通会话身份**：分支持久化、重启后仍在、出现在会话列表中（与源会话同一工作区，插在源会话之前）。tab 内提供“在主视图打开”。分支本身可以再分支、再编辑。 |
| FR-22 | P0 | **命名**：续问分支命名为“<源标题> · 自第 N 轮”，编辑分支命名为“<源标题> · 改第 K 轮”；用户可以照常重命名。 |

### 6.5 给模型的分支说明

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-23 | P0 | 根据持久分支记录，在分支的首次非空 `agent/pre-step` 决策中追加**一条**上下文消息（来源 `plugin:side-branch`），由原生循环提交。仅检查分支自有的已提交说明来去重；若请求准入中止或尚未提问就重启，下次准入重新构造。不得只将说明预先放入队列：真实 DSH 退出会取消未提交队列，测试已确认。内容包括：<br>① 分支位于第 N 轮之后 / 第 K 轮之前，之后的 X 轮对话未继承；<br>② 可能改动的文件路径（作为 JSON 数据引用），使用或修改前重新读取；<br>③ 源会话可能仍在同一工作区工作。<br>说明不把继承历史降级为“仅供参考”，分支是该历史的延续。 |
| FR-24 | P0 | 只写入轮次数和文件路径，**不得**注入切点之后的任何对话内容。 |
| FR-25 | P0 | **不修改系统提示词**，说明只以消息形式追加在继承前缀之后，保证前缀与源会话逐字节相同，保留复用缓存的可能。 |

### 6.6 多实例与生命周期

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-26 | P0 | **多实例与恢复**：同一源会话可以同时打开多个分支 tab，每个 tab 绑定一个分支会话；tab 标题为“改第 K 轮”或“自第 N 轮”。右侧栏布局按源会话保存，刷新或重启后 tab 恢复并重新绑定分支会话。 |
| FR-27 | P0 | **关闭 tab**：<br>• 分支没有自有的用户消息（例如打开了编辑但没发送）：静默归档；<br>• 分支有自有消息：弹出对话框，选项为“保留”（默认）或“归档”，并提供“记住我的选择”；<br>• 分支仍在运行：额外提示。<br>归档沿用 DSH 原生归档，默认隐藏、可撤销。删除能力以 DSH 是否支持为准，MVP 不提供。 |
| FR-28 | P1 | **设为主线**：在主视图打开分支，并可选择同时归档源会话。 |
| FR-29 | P1 | **分支列表**：列出当前会话派生出的全部分支（按 `parentSession` 血缘），可以重新在侧栏打开。 |

### 6.7 并发与安全

| 编号 | 优先级 | 需求 |
|---|---|---|
| FR-30 | P0 | **双写提示**：源会话与分支同时运行时，tab 顶部提示“两个会话正在同一工作区工作”。文件工具受 `FS_STALE_VERSION` 防护；shell 改动不受防护，需在提示中说明。 |
| FR-31 | P0 | **不提权**：插件自身不提升任何权限；分支的权限只能由用户在原生权限选择器中修改。 |
| FR-32 | P0 | **主会话零副作用**：创建、使用、关闭分支都不在源会话日志中追加任何事件。 |
| FR-33 | P2 | **工作区隔离（研究）**：在独立的 git worktree 中运行分支，并尽量还原到切点时刻的文件状态（基于 `workspace-changes` 的轮次快照或其他机制），从根本上消除漂移。 |

### 6.8 异常处理

| 场景 | 期望行为 |
|---|---|
| 源会话需要格式迁移 | 按原生规则提示（可以导航到源会话），不自动迁移 |
| 源会话没有可用轮次 | 入口禁用并说明原因 |
| 切点之后源会话发生过压缩 | 分支不受影响（继承前缀不含压缩事件） |
| 继承前缀超过所选模型的上下文窗口 | 发送前提示改选模型或更早的起点（P1）；P0 至少把错误透传为可读信息 |
| 分支创建成功，但设置模型或权限失败 | 不发送首条消息，tab 显示错误并允许重试；不得以错误配置运行 |
| 源会话在分支存续期间被归档 | 分支不受影响；锚点栏显示“源会话已归档” |
| 刷新或重启时编辑尚未发送 | tab 恢复后仍处于编辑态；若草稿丢失，重新预填原文 |

## 9. 技术方案要点（推荐路线，不构成约束）

### 9.1 客户端（Client 半部）

- **入口**：在 `conversation.chat.assistant-actions` 注册两个按钮。props 只有 `messageId`，所在轮次号由 `turnOutline` 或 Host 路由解析。
- **创建分支**：客户端通过 DSH 已认证连接的 `/api/side-branch/create` 请求 Host 统一完成原生 fork、模型/权限初始化、重命名和上下文注入。Host 调用 `sessionController.fork({ sessionId, atSeq, allowMigration: false })`；初始化模型使用会话局部选择接口，避免调用会写全局默认的 `selectModel`。只有持久状态 ready 才把分支交给原生输入框；请求 ID 用于重试去重。
- **tab**：`ctx.sidebarRightTabs.register` 注册类型，资源地址形如：
  ```
  dsh-resource://side-branch/session/<childId>?source=<sourceId>&mode=edit&turn=K
  ```
  正文 retain 分支的 `SessionReference`，通过 `SessionProvider` 渲染 `conversation.content` 组件（`variant: "embedded"`，固定 Chat 视图），做法同 `dsh-client-ui-subagent` 的 `SidebarChatTab`。
- **编辑预填**：调研原生输入框的草稿接口（M0）；不可用时走降级方案 B。

### 9.2 Host 端（Host 半部）

- **`anchor-info` 路由**：
  - 计算切点（FR-8）；
  - 返回第 K 轮首条人类消息的完整原文；
  - 返回漂移清单（FR-9）。
  - 读取事件时，优先用在线 Agent 的 `session.snapshotEvents()`，否则用 `ctx.sessionQuery.observeSession(id)`（用完释放）。
- **统一初始化与持久记录**：
  - 新建分支的初始化期间阻止其运行，不影响源会话或其他 agent；
  - 在插件专用存储域中记录来源、请求 ID、初始化状态、原问题、配置和文件清单；
  - 清除**新分支**继承的待处理队列（源会话可能在切点之前就排队了后续问题；仅截断日志不足以阻止其被执行），保留继承的已完成历史；
  - 在首个实际准入步骤根据持久记录加入说明，检查分支自有日志来去重，避免退出时队列被取消导致说明丢失；
  - 不新开 HTTP 服务，不使用无鉴权的 `webServer.register`，统一使用 `connection.fetch.register` 的 owner 认证通道。

### 9.3 缓存说明

官方 fork 不改系统提示词，继承前缀与源会话逐字节相同，同模型时**可能**复用提供方缓存；换模型则不能复用。历史切点通常不在最近的缓存断点上，不承诺命中率。

## 10. 实现路线对比（决策 D1）

| 维度 | **Y. 原生会话路线（推荐）** | X. side-chat 路线（自建隐藏 agent） |
|---|---|---|
| 同等公民能力 | 天然具备：模型、权限、审批、AI 提问、附件、命令、插话等全部原生 | 需要逐项自建：模型切换（可复用 `@deepseek-ai/dsh-agent` 的 `installModelSelection`）、审批应答（按 agent 注册 `approval/request` 应答者并桥接到 tab）、AI 提问桥接、附件、命令……永远落后于主会话 |
| 持久化与重启恢复 | 原生支持 | 不支持（side-chat 的已知限制） |
| 会话列表 | 会出现（用 FR-27 归档缓解） | 不出现 |
| 依赖的内部接口 | `conversation.content` 组件嵌入（有 ui-subagent 先例）；`ctx.sessions.fork` 是客户端公开接口 | `agents.create` 的 seed 参数、`origin:'subagent'` 隐藏技巧、手工流式 SSE、手工审批桥接 |
| 工作量 | 中：入口、选择器、编辑流、漂移、分支说明、tab | 大：在上述基础上再加完整对话界面 |
| 维护成本 | 低：主会话新增的功能自动可用 | 高 |
| 主要不确定性 | 嵌入组件在右栏中的完整度（审批、提问、模型选择是否都正常）→ M0 验证 | 无法达到真正对等 |

**结论**：推荐路线 Y。若 M0 验证发现嵌入组件存在无法绕过的缺陷，再评估退回路线 X。
