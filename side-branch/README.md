# 岔路 · Side Branch

从一段对话的历史节点，走出另一条路线。

项目目录：仓库中的 `side-branch/`。插件显示名为 **岔路 · Side Branch**，npm 包名为 `dsh-side-branch`。上一级目录用于存放多个独立插件。支持 Windows 与 macOS。

DSH Desktop 插件：从任意已完成轮次在右侧栏继续，或者修改某一轮的用户提问，从前一轮重新开始。分支是**普通 DSH 会话**，使用原生对话和输入框，支持模型选择、权限设置、工具调用及原生交互。

例如：主会话已经到第 5 轮，想修改第 2 轮的问题。在第 2 轮提问气泡下方、复制旁点击“编辑”，在原气泡中修改并保存，主视图打开修改后的版本并重新发送；点“分叉”则直接在右侧创建分支，保留第 1、2 轮的完整提问和回答，从第 2 轮之后继续，输入框保持空白。旧会话保留。

当前 DSH 历史日志只能追加，无法原地改写已发送的事件；“编辑”通过新的对话版本保存修改，不会伪装成对原日志的原地修改。含附件的历史提问会进入新版本的原生输入框，重新添加附件后再发送，避免丢失附件。

## 当前状态

版本 `0.1.0`，面向 DSH `0.2.1-rc.2` Desktop / Web GUI，Node.js 22 及以上。零 npm 运行时依赖，无安装脚本、后台轮询进程或独立服务器。

- 已用安装包里的真实 DSH 服务验证 fork、权限和模型继承、未来问题排除、日志持久化与进程上下文重新创建后的恢复；模型使用本地假适配器，不发送真实 API 请求。
- 客户端按发布的原生侧栏和对话接口实现，并有行为测试。实际桌面页面的点击、排版以及完整审批交互验收仍需在安装后完成；代码与服务测试不能替代页面验收。
- 本次开发没有安装进当前正在使用的 profile，没有关闭、重启、刷新或重新配置现有 DSH，没有操作其他任务会话。

## 使用方式

完整图文说明见 **[使用指南](docs/使用指南.md)**。简要步骤：

1. 提问气泡的复制旁有“编辑”和“分叉”两个按钮。编辑先展开原文，保存后在主视图打开修改后的版本；分叉在右侧保留选中轮次的完整问答，从本轮之后继续。轮次尚未结束时不可用。
2. 也可以在某轮回复末尾点击“侧栏分支”，从该轮之后继续；点击“编辑本轮提问”，从上一个已完成轮次重新开始。
3. 也可以从右侧栏 `+` 的引导页选择“岔路 · 侧栏分支”，再选择模式和轮次。长会话可以按提问或回答预览筛选。
4. 分支初始模型和思考强度取源会话当前值，权限也取当前值。可在原生输入框内选择其他模型或修改权限。
5. 编辑模式预填原问题，修改后再发送。已存在的草稿不会被覆盖；原问题的附件会提示重新添加。
6. 查看顶部的文件改动提示，然后按正常会话使用。支持“在主视图打开”。

没有最终回复、或回复之后仍有工具/错误活动的轮次，不提供“从该轮之后续问”；已结束但回答失败的轮次仍可在选择器中编辑其人类提问。

## 会话与文件的边界

**对话历史分支不会回滚磁盘文件。** 主会话与分支使用同一个当前工作目录。分支顶部会列出切点之后可能变动的文件，并在首次实际模型请求中加入说明，要求依赖或修改文件前重新读取。

DSH 文件工具的读取及版本检查继续生效；shell、外部程序和未被记录的改动不构成完整的文件隔离。文件列表来自可用的原生改动摘要及工具调用记录；调用过工具不等于修改成功，因此显示的是“可能改动”，不能当作精确差异审计。

插件不会降低历史分支的编辑权限，也不会主动提权。创建时只把当前源会话配置应用于新分支，不修改源会话、全局模型默认值或其他会话配置。之后用户在**原生**模型选择器中手动切换模型，可能按 DSH 原有行为同时改变未来新会话的默认模型；插件不会尝试回写全局默认值来抵消该行为。

## 保留、关闭与恢复

- 分支是持久会话，会显示在原生会话列表中。
- 折叠侧栏或切换标签不会销毁、取消分支。
- 点击分支内部的“关闭分支标签”：没有自有消息、排队输入或后台工作时自动归档；有消息时可以保留或归档，并可记住选择。
- 点击 DSH 原生标签的 `×`：原生关闭回调不能等待异步确认。插件先保留会话并记录待处理项，再显示恢复/归档选择；如果用户已切换会话，则不会抢走当前页面，可从“侧栏分支”引导页处理待处理项。
- 运行中的分支不会因为关闭标签而被隐式停止。要归档运行中的分支，请先用原生停止操作。
- 归档可从 DSH 的已归档会话列表恢复。插件不删除会话目录。
- 原生侧栏保存标签布局，插件保存分支来源。刷新后重新绑定原生 SessionReference，继续使用已有会话。

首次提问前退出 DSH 不会丢失分支说明：说明内容依据持久记录在下一次请求准入时加入，并由原生循环写入日志。已经提交过的说明不会重复插入。

## 安装

在正在运行的 DSH 中，进入 **插件 → 添加插件旁的下拉箭头 → 安装第三方插件**。

在“包名或地址”中输入此插件独立目录的绝对路径，然后点击安装：

```text
/Users/<你的用户名>/dsh-plugin/side-branch     # macOS
E:\dsh-plugin\side-branch                      # Windows
```

安装成功后，在已安装插件中启用 **岔路 · Side Branch**。不要填写上一级仓库根目录，它只是多个插件的总目录。

也可以先在本目录执行 `npm pack --pack-destination artifacts`，再安装生成的包 `artifacts/dsh-side-branch-0.1.0.tgz`（同样填写绝对路径）。

使用官方插件界面即可，不需要手工编辑 profile 或覆盖 DSH 安装文件。若官方结果显示需要重启，以该结果为准，插件不会自行重启 DSH。

卸载时，在官方插件管理器中移除 **岔路 · Side Branch**（包名 `dsh-side-branch`）。

卸载不会自动删除或归档已有原生分支会话。已有分支可以从 DSH 会话列表继续打开。

## 开发与验证

源代码采用无需构建的 ESM Host 文件与经典脚本格式的 Client ModuleLoader 文件：

| 文件 | 作用 |
|---|---|
| [index.js](lib/index.js) | 已认证的 DSH 连接路由、生命周期与服务挂载 |
| [service.js](lib/service.js) | 原生 fork、初始化门禁、局部配置、持久来源记录、关闭策略 |
| [history.js](lib/history.js) | 轮次边界、原问题、改动路径与上下文说明 |
| [client.js](lib/client.js) | 原生对话嵌入、起点选择、草稿初始化、标签恢复 |
| [需求文档](docs/侧边追问插件-需求文档.md) | 已确认范围与验收要求 |

使用 Node.js 22+ 运行独立单元测试（Windows / macOS 命令相同）：

```sh
npm test         # 等同 node --test tests/*.test.js
npm run check    # node --check 各 lib 文件
```

真实 DSH 集成测试只在项目内的隔离目录中读取发行包副本、创建测试会话，使用本地模型适配器。它不访问当前 DSH GUI 的端口、不读取真实会话或凭据，也不写入用户 DSH home。具体运行方式与验证范围见 [隔离集成测试说明](scripts/INTEGRATION.md)。运行命令：

```sh
npm run test:integration    # 等同 node scripts/run-integration.mjs
```

首次运行会从本机安装的 ASAR 提取测试依赖到项目目录。默认查找 macOS 的 `/Applications/DeepSeek Harness.app/Contents/Resources/app.asar`（或 `~/Applications/…`）以及 Windows 的常见安装位置；通过 `DSH_TEST_ASAR` 环境变量可指定其他位置。

`scripts/live-ui.ps1` 是仅限 Windows 的手动验收辅助脚本（Win32 UI Automation），测试不依赖它。

运行 `npm run test:browser` 可使用本机 Chrome，在隔离页面中验证安装包的真实用户气泡、复制栏和插件入口，包括同行布局、原文复制、防重复创建、失败重试与卸载恢复；它不会连接当前 DSH 窗口。先运行一次集成测试以准备提取的运行时依赖。

## 已知边界

- 用户气泡入口通过原生 `conversation.chat.node` 的 `user` 渲染键包装实现，将独立的“编辑”“分叉”加入原生操作栏，与复制并列；保留原生正文、附件与复制操作，停用插件时恢复原渲染器。本次已用安装包的 DSH 0.2.1-rc.3 原生组件验证。请求按原生轮次定位以兼容旧后端，新后端再核对原提问 ID；不支持从同轮的中途补充消息改写起点。
- 首轮编辑创建空历史原生会话，因此原生 `parentSession` 为空；来源在插件存储中保存。其余轮次使用原生 fork 血缘。
- 原问题的图片和文件附件不会自动重新附加；在原生输入框重新添加即可。已有的继承历史附件仍由 DSH 管理。
- 子代理会话不能作为源；普通分支可以作为源。
- 起点是固定快照；创建后不自动吸收源会话后续对话或刷新创建时的改动清单。
- 不估算费用、不保证 KV 缓存命中，也不实现 Git worktree 隔离。
- 内嵌原生对话依赖当前 DSH 发布接口；升级 DSH 后应重新验证，缺少关键接口时插件会提示不兼容。
- 分支标识由 `crypto.getRandomValues` 生成，不依赖仅安全上下文可用的 `crypto.randomUUID`；因此经 `dsh web --host <局域网地址>` 以普通 HTTP 打开时也能创建分支。
- 初始化失败的分支保持不可运行并尽力归档；普通重试会恢复**同一个分支**及其保存的配置，成功后撤销插件执行的归档。若原生创建过程在身份持久化之前被异常中断，插件不会猜测并重复创建；检查原生会话列表后，可以显式选择另建分支。
