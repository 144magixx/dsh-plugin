## 5. 0.1.0 修订（2026-11-09 13:20）

- **Markdown**：原因是原生 `MarkdownText` 是 `React.memo` 组件（对象），旧代码只接受函数，于是退回纯文本。已改为同时接受 memo / forwardRef 组件。
- **图片**：输入框支持粘贴、拖入、📎 选择；Host 先校验模型 `inputModalities`，再经 `ctx.attachments.admitPromptContent()` 存为原生附件。上传路由（create / prompt）请求体上限 28 MB，其余仍为 256 KB；请求体读取的 2 秒期限不变。
- **模型**：新增 `models`（目录 + 源会话当前模型）与 `model`（按线程切换，调用会话内 `agent.model.select`）路由；视图返回当前模型名与思考强度。模型目录在后台加载，不阻塞长轮询。

## 6. 修订：回答里的图片与文件链接（2026-11-09 15:30）

用户反馈：回答里的图片只显示替代文字，文件名不能点击跳转。

- 原因：浮窗只渲染了 Markdown 组件，没有提供原生会话视图里的图片地址解析（`pathImages` / `fileImages`）、链接委托（`MarkdownDelegateProvider`）和产出文件引用（`fileMentions`）。
- 修复：Host 从隐藏会话的工具调用中提取 `present`、`write`、`edit` 等涉及的文件路径，并在视图中返回工作目录；Client 用原生 `MarkdownDelegateProvider` 包住回答，本地图片走 `api/file`，文件引用与链接用 `sidebarRight.openResource` 在源会话的右侧栏打开，网页链接按原生方式打开。
- 验证：单元 + 真实 HTTP 测试 28 项、真实运行时集成测试 7 项通过；Chrome 冒烟测试（React 18 + 按原生约定写的 Markdown 桩）中，`![…](brute_force_vs_shortest_path_ledger.png)` 解析为 `api/file?path=<工作目录>/…png`，反引号文件名变成可点击引用，点击后打开 `dsh-resource://file/session/<源会话>/<绝对路径>`。真实界面仍待刷新后确认。

## 7. 修复：划词提问点击无反应、侧栏页签空白（2026-11-09 15:55）

- 根因：原生 `MarkdownText` 渲染代码块时读取 `labels.code`，插件没有传 `labels`。回答里只要有代码块就会在渲染时抛错（`Cannot read properties of undefined (reading 'code')`），浮窗和划词按钮共用的界面树被整体卸载（点击无反应）；侧栏页签会打开上次的提问，同样崩溃（空白）。早先那条不含代码块的提问不受影响。
- 修复：传入与原生会话相同的 Markdown 标签；每条消息和浮窗、页签各自加错误边界，单条渲染失败只退回原文或显示提示，不再拖垮整个界面；本地图片传入原生文件拖拽服务（缺失时用空实现），避免悬停图片时报错；去掉会让代码块强制断行的样式。
- 复现与验证：新增 `tests/browser/build-real.mjs`，从安装包提取真实外壳的 React、ReactDOM 与 ui-primitives，在 Chrome 中加载插件；用你本机两条真实隐藏会话的日志回放。修复前，含代码块的那条报上述错误、页签空白；修复后两条都正常渲染（代码块、表格），无报错，浮窗可打开并从历史切换到该条。单元测试 29 项、集成测试 7 项通过。已停用再启用插件（applied）。
