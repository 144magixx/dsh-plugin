# 会话导航使用指南

会话导航帮助你凭“最近聊过什么”认出会话。原标题保持稳定，近期话题与摘要在后台更新；原来的 DSH 会话界面继续用于阅读和对话。

## 安装与模型准备

从 [dsh-plugin 仓库](https://github.com/144magixx/dsh-plugin) 获取代码，将 `session-navigator` 这个子目录作为本地插件安装。可在 **插件 → 添加插件旁的下拉箭头 → 安装第三方插件** 中输入绝对路径：

| 系统 | 示例 |
|---|---|
| macOS | `/Users/<你的用户名>/dsh-plugin/session-navigator` |
| Windows | `E:\dsh-plugin\session-navigator` |

安装目标是子目录，不是仓库根目录。插件没有运行时 npm 依赖，无需先执行 `npm install` 或构建；所需 React 和 Harness 服务由 DSH 提供。

启用前确认 DSH 的模型列表中已有 `codex-relay / gpt-6-luna`。这是默认摘要模型；服务地址和密钥保留在 DSH 原有模型配置中，不写入本插件仓库。如果你的服务商或模型 ID 不同，按本指南的[配置](#配置)修改对应字段。

模型暂时不可用时，仍可浏览会话标题、最近提问和已经缓存的摘要。

## 页面与原生侧栏

侧栏的 **会话导航** 打开独立导航页面，不替换原生会话列表。

### 会话列表

每个会话显示两行主要信息：

1. **原标题**：读取会话已有标题，不自动重命名。
2. **最近话题 / 最近提问**：摘要覆盖当前内容时展示简短话题；新内容尚未概括、正在排队或生成失败时展示最近提问。

列表还显示工作区、时间以及摘要状态。超长问题在列表中截断显示，完整的可用提问片段在详情中查看；内容提取本身也有长度上限。

### 详情与悬停

单击会话后，详情区域展示：

- 最近话题与一句话摘要。
- 最近一次用户提问。
- 最多三个此前话题。
- 会话更新时间、摘要更新时间与已记录的访问时间。
- 正在后台更新、已有新内容、自动摘要暂停或生成失败等状态。

较旧摘要会标注“之前的摘要”。鼠标悬停会话行可以预览，键盘聚焦并选择会话也能查看详情。原生侧栏会话行的悬停卡片展示相同的缓存信息；悬停不会触发模型生成。

### 打开会话

- 双击列表项，或在详情中点击 **打开会话**。
- 使用 ↑ / ↓ 移动选择，Home / End 移动到已加载列表的首尾，Enter 打开。
- 搜索框中按 ↓ 可进入结果列表；输入法组合输入期间不会把 Enter 误当作打开操作。
- “返回对话”回到当前原生会话。

实际打开会话时记录最近访问，包括从原生侧栏打开。只在导航页选中或悬停查看详情不会作为一次会话访问。

归档会话可以查阅已有信息，但不能直接打开；需先在原生侧栏取消归档。

## 搜索、筛选与排序

搜索按关键词匹配这些已提取或缓存的字段：

| 范围 | 内容 |
|---|---|
| 会话标题 | 已有标题 |
| 最近话题 | 模型生成的短话题 |
| 最近讨论 | 模型生成的一句话摘要 |
| 此前话题 | 摘要中保留的话题标签 |
| 最近提问 | 最近一次用户提问的可用文本片段 |

匹配不区分英文大小写。这里不做整段历史正文检索，也不是语义向量搜索。较早消息没有进入近期片段或历史话题标签时，不保证能够搜到；需要查找全部历史消息时可使用[会话搜索插件](<../../session-search/README.md>)。

可选择工作区，并按以下方式排序：

- **最近访问**：优先按插件记录的实际打开时间排列，再按内容更新时间补位。首次使用时不会推测安装前的访问历史。
- **最近更新**：按会话内容更新时间排列，适合查看近期活跃任务。

默认不显示归档会话；勾选“包含归档”可一起查找。结果较多时使用“加载更多”。列表只包含普通会话，不包含子 Agent 任务。

## 摘要何时生成

### 首次启用与历史会话

默认启动回填上限为 **12**：插件从最近更新的非归档普通会话中选择候选，检查哪些需要生成摘要。已有有效缓存的会话不会因此重复生成。

其他历史会话仍可通过原标题和最近提问查看。实际打开这些会话时，若自动摘要开启且该会话未暂停，插件会按需安排后台摘要。若希望明确更新某个会话，可点击 **更新摘要**。

### 新内容与后台队列

新提问会先进入导航信息，不需要等待模型。通常在一轮对话完成后，插件经过短暂合并等待，再检查是否需要生成新的摘要。

摘要调用独立于主会话，不创建子 Agent，不要求主模型附带摘要，也不会向原对话插入“请总结”之类的消息。它只处理有长度上限的近期正文及必要历史线索，排除运行时提示、工具日志和子 Agent 通知。

**更新摘要**会安排后台任务并立即返回排队状态。完成后，变更通知驱动界面刷新。即使该请求仍在进行，你也可以继续打开原生会话；导航不等待模型完成。

### 暂停与手动更新

每个会话可以单独选择 **暂停自动摘要**。暂停状态会保存，之后的新内容仍会更新最近提问，但不自动生成摘要。

暂停后仍可使用 **更新摘要**，这次手动请求不会取消暂停状态。选择 **恢复自动摘要** 后恢复自动更新；若全局 `autoSummarize` 关闭，则需要先调整全局配置才能恢复自动任务。

## 模型慢或暂时不可用

插件默认采用以下限制：

| 项目 | 默认行为 |
|---|---|
| 单次生成超时 | 20 秒 |
| 同时生成数量 | 2 个会话 |
| 待处理队列 | 最多 48 个会话 |
| 连续失败保护 | 连续 3 次生成失败后，自动任务冷却 60 秒 |
| 旧内容 | 保留已有摘要，并继续显示最近提问 |
| 手动操作 | 可查看错误后手动更新；不自动切换模型 |

冷却保护针对后台自动任务，手动更新仍可主动尝试。队列已满时，手动请求会提示稍后重试。原摘要过时或生成失败不会阻止浏览、筛选、查看详情及打开会话。

如果显示“实时更新暂时中断”，已有内容仍可查看；点击“重新连接”。插件会重连变更流，不通过反复轮询会话或模型来替代实时通知。

## 配置

当前配置通过安装包默认值和当前 DSH profile 的补丁管理，并在插件加载时手动校验字段名称、类型与范围。不依赖配置编辑器自动生成表单。

在当前 profile 的 `cordis.patch.yml` 中覆盖 ID 为 `session-navigator` 的条目。例如，下面列出全部可配置项：

```yaml
- id: session-navigator
  name: dsh-session-navigator
  config:
    provider: codex-relay
    model: gpt-6-luna
    autoSummarize: true
    debounceMs: 1200
    timeoutMs: 20000
    concurrency: 2
    initialSummaries: 12
    failureThreshold: 3
    cooldownMs: 60000
    maxQueue: 48
```

`config` 是整段覆盖，不是深度合并；建议以完整配置为基础修改，未提供的字段回到插件默认值。修改后通过当前 DSH 的插件重载流程使配置生效，并检查插件状态。不要直接修改已安装包中的默认补丁来保存个人设置。

| 字段 | 默认值 | 含义与允许范围 |
|---|---|---|
| `provider` | `codex-relay` | DSH 中已有的服务商路由 ID，非空字符串，最多 160 字符 |
| `model` | `gpt-6-luna` | 该服务商可用的模型 ID，非空字符串，最多 160 字符 |
| `autoSummarize` | `true` | 全局自动摘要开关；关闭后仍可手动更新 |
| `debounceMs` | `1200` | 自动更新的合并等待毫秒数，整数 0–60000 |
| `timeoutMs` | `20000` | 单次摘要生成超时毫秒数，整数 100–120000 |
| `concurrency` | `2` | 同时生成数量，整数 1–3 |
| `initialSummaries` | `12` | 启用时的最近会话回填上限，整数 0–30；设为 0 关闭启动回填 |
| `failureThreshold` | `3` | 连续失败多少次后进入冷却，整数 1–10 |
| `cooldownMs` | `60000` | 自动任务冷却毫秒数，整数 100–300000 |
| `maxQueue` | `48` | 等待生成的会话队列上限，整数 1–200 |

服务商与模型字段只引用 DSH 已配置的模型。插件不接受单独的 API Key 或服务地址字段；不要把凭据写入这个补丁或提交到仓库。

## 数据保存与测试边界

原标题和用户/助手正文来自会话日志。插件以只读方式提取导航信息，不重命名会话、不改写历史消息，也不将生成的摘要追加到原会话。

话题、摘要、访问时间、暂停状态由 DSH 的 `storageDomain` 管理并持久化，使用插件独立的数据域。已有缓存可跨重启复用；模型调用和前端临时请求随插件卸载清理。

模型自动概括可能存在偏差。最近提问保留原文线索，旧摘要有明确标签；需要精确信息时打开原会话核对。

自动化测试仅使用合成事件、合成会话和受控的模型响应，仓库不附带真实对话样本。测试命令：

```sh
npm run check
npm test
```

单元测试覆盖逻辑和客户端状态行为，不等同于实际安装后的界面验收。当前文档不声称已经通过真实页面截图验证。

## 常见问题

**只有最近提问，没有摘要？**

可能尚未轮到后台任务，或该会话不在启动回填范围内。打开它或点击“更新摘要”；同时检查是否暂停自动摘要，以及 DSH 中配置的模型是否可用。

**旧摘要为什么还显示？**

最新问题会立即提供导航线索，旧摘要作为辅助记忆保留，直到新的摘要生成完成。详情中的“之前的摘要”表示它尚未覆盖最新内容。

**刚安装时为什么不能按以前的访问顺序排列？**

访问记录从插件开始观察到实际会话打开时累计，安装前没有的记录不会被推测。可以先按“最近更新”查找。

**想找很早的一段话，为什么搜不到？**

导航搜索基于标题、近期提问和缓存摘要，历史正文不在全文索引范围内。请使用[会话搜索插件](<../../session-search/README.md>)检索历史消息。

**主会话模型需要也换成 Luna 吗？**

不需要。主会话继续使用你选择的模型；导航摘要独立使用本插件配置中的服务商和模型。
