# DSH 插件开发约束

适用于本仓库及 `session-navigator/`。先检查 Git 状态，保留已有修改、插件数据和本地安装配置。

## 更新失败案例与机制（2026-11-06）

用户在 2026-11-05 至 2026-11-06 报告更新时黑屏、退出后仍为旧版。事故时已核对 DSH Desktop 0.2.1-rc.5。更新包和签名通过，安装尚未交给 ShipIt。

该版本安装前锁定 API，新请求返回 503，并等待已经进入 `connection/request` 的请求完成，主进程等待上限为 10 秒。HTTP bridge 直到响应体结束才完成。原 `/api/session-navigator/watch` 与另一插件 `/api/session-favorites/changes` 均为永久 NDJSON 流，只在页面取消或插件销毁时结束，因此可使排空超时、安装中止。25 秒心跳不会结束请求。黑屏为用户观察；未实际复现完整黑屏或崩溃，不把候选解释写成已确认的渲染器崩溃。

## 强制开发要求

1. 不允许被 Host 排空流程追踪的 HTTP 响应永久占用请求。优先使用宿主支持的可取消推送；HTTP 订阅必须有服务端硬性截止时间，显著小于已核对的更新等待期限。本次修复目标最多 3 秒，不能配置为永久等待，不能只依赖客户端主动关闭。
2. 正常结束、请求 abort、慢消费者、插件 dispose 与异常必须统一清理 timer/监听/订阅，关闭幂等，缓冲有界。接收请求体的等待也必须可取消、有界。
3. 客户端将正常 EOF 视为订阅轮换，503 使用有界退避；始终只有一条有效订阅，停用后不重连。相同 revision 的轮换不能重复刷新全量列表或生成模型摘要；服务重载后 revision 重置需要正确识别。
4. 安装或升级测试必须覆盖活跃订阅时锁定、拒绝新请求503、旧请求在期限内完成、解锁恢复，以及取消、停用、反复启停和资源清理。需真实 HTTP bridge/响应体集成验证，不能仅测试构造 Response。
5. 插件错误局限自身面板；不得清空工作区、阻塞退出/更新、擅自杀宿主或取消宿主的安全停止检查。
6. 区分测试通过、安装生效与真实应用更新成功。未获授权不得触发 DSH 更新、重启或中断用户当前任务。安装优先使用插件管理器热应用，验证 profile link、版本、接口与实际启用状态；需要重启时如实说明。
7. 不擅自新增依赖、卸载插件数据、提交或推送 Git 变更。修复需保留会话原标题、收藏/摘要数据与既有正常功能。
