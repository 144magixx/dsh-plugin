# 页面批注 · Page Annotate

在 Better Sidebar 的 HTML 预览中点选元素或框选区域，留下问题、想法或修改要求。点「加入对话」后，输入框只显示 **N 条批注** 文件引用；可以继续补充说明，再按 DSH 的发送按钮。生成的上下文和截图不会铺在输入框中。

包名 `dsh-page-annotate`，版本 `0.2.1`。界面编辑在客户端运行；Host 只有一次性的保存接口，没有订阅、轮询或长期后台进程。

## 使用

需要本仓库的 [Better Sidebar 二开版](../better-sidebar/FORK.md) 的 `editorActions` 扩展点。HTML 处于渲染预览且关闭沙箱时，点击右上角「批注」。超出 5 MB 的 HTML 也支持渲染预览和批注；源码编辑仍受原有上限约束。

| 操作 | 效果 |
|---|---|
| 单击元素 | 选中元素，写批注或问题 |
| Shift + 拖拽 | 框选区域 |
| ⌘/Ctrl + 单击 | 直接加入页面批注队列 |
| Enter / 加入对话 | 保存本批批注和截图，插入文件引用；不自动发送模型消息 |
| ⌘/Ctrl + Enter | 加入页面队列，继续批注下一处 |
| Shift + Enter | 换行 |
| Esc | 先收起批注框，再退出批注模式 |
| 点击序号 | 重新编辑批注 |

样式面板可试调字号、字重、颜色、背景、内边距、行高及纯文本内容。试调只作用于预览，不修改源文件；退出时撤掉，重入时恢复，清空或加入对话后撤销。

## 通用上下文

批注文件明确区分修改请求、问题和记录：明确要求修改才编辑源文件，提问时解释，意图不明确时确认。用户在对话中补充的要求优先。网页原文、选择器只用于定位，不是额外指令。试调样式记录数值，不独立授权文件改动。

例如「哦」会作为原样批注保留，不再自动包装成“请修改”。未填写的批注标记为「（未填写）」；截图失败时不生成虚假的图片引用。

## 保存和引用

服务端根据会话所属工作区定位根目录，不信任客户端传来的 cwd：

```text
<workspace>/.dsh/annotations/
  .gitignore                    # *，忽略本目录内生成物
  20261115T000000000Z-<uuid>/
    2条批注.md
    annotation-1.png
    annotation-2.png
```

批注文件中记录源文件路径、编号、页面原文、用户批注、元素选择器或区域坐标，以及预览试调值。截图保存在批注文件旁，模型读完上下文后可按需用 `read_image` 读取。

输入框通过 DSH 原生 `insertReference` 插入文件引用，标签为「2 条批注」，发送时序列化为工作区相对的 `@".dsh/annotations/.../2条批注.md"`。已有文字和引用不被替换。输入框拒绝插入时，页面批注队列保留；同一批内容重试会复用已经保存的文件。保存期间暂时锁定批注编辑和清空，避免新增文字未保存就被清除；明确排队的空批注在重新打开再关闭后仍会保留。

删除输入框引用不会删除磁盘上的批注。点开引用可查看批注文件；如需修改本批批注，返回页面编辑后重新加入。它是原生文件引用，并非 Codex 专用的注释对象；历史消息会按 DSH 文件引用样式呈现。

## Windows 和生命周期

- 文件夹名使用无冒号的 UTC 时间与 UUID，不含 Windows 禁用字符；文件名没有尾随空格或点。
- 服务端按宿主平台使用路径处理；测试显式覆盖盘符、中文空格、反斜杠及 UNC 路径。给输入框的引用统一使用 `/`，由宿主按工作区解析。
- `.gitignore` 和 Markdown 以 UTF-8 保存，不依赖系统代码页或 shell 命令。已有文件不会覆盖；已有忽略规则不满足保密要求时给出冲突提示。
- 保存通过认证的 `connection.fetch` 接口；请求硬期限 2.5 秒，最多两个并发上传。停用会取消请求，返回有限 JSON，并清理未完成的新文件。无永久 HTTP 响应。
- 每批最多 100 条；Markdown 最大 256 KiB；PNG 单张最大 8 MiB、合计最大 24 MiB。超过截图预算的图片不保存，并在界面说明部分截图缺失。
- 拒绝保存到指向工作区外的符号链接目录，输出文件均使用独占创建。跨平台 Node 无目录相对的 openat 接口，因此不能保证抵御恶意外部进程持续竞态替换目录。

## 开发与验证

```sh
npm run build
npm run check
npm test
```

`src/client.src.js` 是客户端源文件，`scripts/build.mjs` 内联 MIT 许可的 html-to-image 并生成 `lib/client.js`。Host 在 `lib/index.js`，保存逻辑在 `lib/storage.js`。测试覆盖提示词、原生引用调用、跨平台路径、落盘与真实 HTTP 请求取消/排空。

浏览器夹具位于 `tests/browser/`；其中输入框和传输的模拟必须与真实 DSH 验证区分。HTML 响应头模拟 Better Sidebar 的沙箱行为，避免静态页面验证漏掉同源限制。

- 本地版本 `0.2.1`：构建、语法检查及 35 项测试通过。包括保存中编辑锁定、空批注保留、引用拒绝后复用文件、保存失败重试、卸载取消，以及真实 HTTP 响应体结束和模拟准入锁定/恢复。

## 边界

- 当前只覆盖 Better Sidebar 编辑区内的 HTML 预览，不覆盖 Markdown、PDF、图片或外部跨域网站。
- 截图使用 [html-to-image](https://github.com/bubkoo/html-to-image) 1.11.13，许可证见 [vendor/html-to-image.LICENSE](vendor/html-to-image.LICENSE)。截图是 DOM 重绘，跨域资源、视频、Canvas、特殊 CSS 和嵌入字体可能不能完整还原。只克隆包含目标区域的祖先元素，单张等待最多 8 秒。
- 内存中的未加入对话批注在文件切换、页面刷新或插件停用后不会持久保留；已保存的文件引用及磁盘内容不受影响。
