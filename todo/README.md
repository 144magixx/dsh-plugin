# 待办 · Todo

仿 iPhone「提醒事项」的 DSH 待办插件。设计稿见 [todo-design](../todo-design/README.md)。

- **完整页面**：左侧导航「待办」。上方是今天、计划、全部、旗标、已完成五个智能列表，下方是「我的列表」，可新建、改名、换颜色、删除。右侧按上午 / 下午 / 今晚（计划按日期，全部按列表）分组显示事项。
- **右侧卡片**：显示今天到期和逾期的事项，可以直接勾选、改标题、新建。在卡片里新建的事项默认今天到期，并关联当前对话。依赖「外部能力」插件提供的卡片栏插槽。
- **截止时间与旗标**：点事项右侧的 ⓘ 设置日期、时间、旗标、列表和备注。逾期的时间标红。
- **关联对话**：事项可以关联一个会话，点标签直接跳回去。会话标题改了，标签会跟着更新。
- **到点提醒**：设了具体时间的事项到期后，在 GUI 顶部弹出横幅，可以「完成」「10 分钟后」再提醒，或「打开对话」。每条提醒只弹一次，多个窗口不会重复。错过超过 12 小时的不再补弹。
- **Agent 读写**：工具 `todo_reminders`，支持 list / lists / add / update / complete / delete / add_list / update_list / delete_list。Agent 新建的事项默认关联当前对话。

## 安装

在 DSH 的 **插件 → 添加插件旁的下拉箭头 → 安装第三方插件** 中填入本目录的绝对路径，例如 `/Users/<你的用户名>/dsh-plugin/todo`，然后启用「待办」。

## 数据与连接

- 数据存在 profile 的 storage domain `dsh_todo` 里，一份文档最多 50 个列表、5000 条事项。卸载插件不会删数据。
- 只有一个接口：`POST /api/todo/action`，每次请求都是普通 JSON，返回后就结束，不保持长连接，不会阻塞 DSH 更新前的请求排空。
- 页面和卡片共用一个客户端 store，每 3 秒查询一次版本号（窗口在后台时 15 秒），版本变了才拉全量。请求失败（包括更新期间的 503）按 6 / 12 / 24 / 30 秒退避，恢复后回到正常频率；插件停用后不再请求。
- 「今天」「逾期」按浏览器所在时区计算；Agent 工具按 Host 所在时区计算。

## 开发

```sh
npm test                    # 单元测试：数据模型、服务、HTTP、工具、客户端 store 与渲染
npm run test:integration    # 从本机 DSH app.asar 只读提取 Cordis 与存储依赖，跑真实存储和 HTTP 响应体
```

`node scripts/live-preview.mjs` 启动本地验证页（真实服务端处理器 + 真实客户端，内存存储，不是 DSH 本体）；`node scripts/preview.mjs` 生成静态对照页到 `artifacts/`。验证结果见 [验收记录](docs/验收记录.md)。

集成测试覆盖：真实 storage domain 持久化；轮询进行中锁定准入并排空（3 秒内完成）；锁定后新请求返回 503；解锁后恢复；取消的请求不残留；工具经原生注册表执行；反复停用 / 启用后路由和工具被移除、数据保留。
