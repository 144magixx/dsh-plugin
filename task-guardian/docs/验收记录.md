# 验收记录

## 0.1.2：PI 过载接管与未生效原因

对用户截图涉及的会话采用官方 JSONL persistence 的 `open(id, 'read')` 只读核实，仅提取请求路由、错误和时间边界：失败轮次在 2026-10-27 14:35:47.087（Asia/Shanghai）以 `PI_AI_ERROR` 结束，守护开关在 14:36:11.590 才持久开启，晚 24.503 秒；期间没有原生 `llm/retry`。当次没有守护重试的首要原因是失败已结束后才开启，插件不会自动重新提交该轮用户任务。

另有可以独立复现的代码兼容缺口：当前 pi-ai SDK 将结构化 provider 错误扁平为 `server_error: Our servers are currently overloaded. Please try again later.`。Harness 适配器没有识别其 5xx 状态，传入 `PI_AI_ERROR` 和原文；默认 normal 重试码列表不含该通用码，因此原生直接委派且计数为零。0.1.1 守护仅允许“预算耗尽”，加上分类器未识别该明确过载句型，会让以后即使提前开启也漏接管。

0.1.2 保留 `await next()` 的原生优先，依据当前已验证的 normal 策略和投影区分预算耗尽、原生不处理该码、服务端 Retry-After 超原生上限三种明确接管边界，再执行严格临时分类。原生仍能处理且预算未完、缺策略/状态、未知错误、永久错误均不自动接管；没有将全部 `PI_AI_ERROR` 加入临时白名单，没有修改原生 always 配置。授权、取消、模型和工具执行边界保持原有机制。

状态 API、持久审计和界面新增具体未接管决定、最近失败结束时间及守护开启时间，计数归零不会再丢失最后的拒绝原因；界面明确提示“开启守护不会自动重放已经结束的失败轮次”。兼容检查的正面文案限定为原生 API 版本匹配。

新增真实 AgentLoop 集成使用本机安装包的 Cordis、LLM、AgentLoop、原生重试、Session/Projection/Query 及 JSONL/JSON 持久化，模型适配器为无网络的本地模拟：开启后精确 PI overload 触发一个已持久化的 30 秒计划，实际产生第二次请求并成功；原生预算未消耗、用户批次只准入一次、同 turn/step、没有工具重放。另验证流内 finish(kind:error) 路径、过载后永久失败仍停止且保留原因，以及关闭时失败再开启不增加请求、不改原会话日志。测试中的等待可控，不代表向真实 relay 发起了付费重试。

最终语法检查、打包检查及 87 项单元/集成测试全部通过（0 失败、0 跳过），包括 36 项重试分类/原生链测试及 6 项真实请求循环测试；现有入口浏览器验收 29 项通过。独立审查发现并修复了“明确内容政策拦截与过载语句混合时应永久优先”的遗漏，最终审查无剩余可操作问题。真实 Windows 和真实上游故障仍未实测。

已通过官方 PluginManager API 更新安装 `dsh-task-guardian@0.1.2`，包管理退出码 0；返回 `restart-required / no-hmr`。当前任务结束后需重启 DSH 并刷新原页面，之后在已开启守护的会话重新发起请求；未自动重放截图中的旧失败，也未修改其他会话的开关。

以下保留 0.1.1 与 0.1.0 的历史验收记录；其旧的“仅预算耗尽”接管描述已由上述 0.1.2 分支判断替代。

## 实际交付范围

- 可执行：按会话授权的临时模型故障守护，原生 normal 重试优先，确认原生预算耗尽后继续无业务次数/总时长上限的可取消退避重试。
- 可执行：三个独立会话设置、原生右侧入口和页签、状态展示、持久记录、审计、OS 排他锁、只读状态工具。
- 可执行：重启时读取已授权记录与原始会话的恢复审查，以及从 durable 原始问题时间重建的 30 分钟倒计时。
- 当前不自动执行：跨重启任务恢复与普通问题超时作答。缺少覆盖停止/撤销路径的可靠恢复授权 fence，以及通用问题可信风险分类/自动来源契约时，保持人工确认。它们没有通过伪造用户消息、审批答案或未声明的会话事件来实现。
- 登录启动：macOS LaunchAgent、Windows HKCU Run 适配器；安装默认关闭。真实系统启停/重新登录没有执行，见平台缺口。

## Inspect 与源码核实

先读取安装包自带 cordis-plugin-development Skill 及 practices、user-actions、host-plugin、ui-plugin 引用。当前会话未暴露 cordis_inspect_list/query 工具，因此只读提取当前安装包，在隔离 Cordis 运行时调用真实 Client Inspect provider 和 Host Inspect catalog 查询函数；没有借此启动替代 GUI 或用户 Agent。

| 核实项 | 结果 |
|---|---|
| Client Slots.listSubTree | 原生 sidebar-right 提供 `sidebar.right.tab.guide.entry`、`sidebar.right.pane.tab`；两者为按 session 的 keyed 扩展点 |
| 指定位置 | “外部能力”下方没有原生插槽。实际入口采用原生右侧“开始”页卡片，详情为独立页签；不读取同伴插件 DOM、不覆盖 guide/body/title/整页 chain |
| Host Event | `agent/request-error` 为 waterfall，默认未处理为 undefined；`agent/request` 为配置 waterfall；`agent/status` 为状态 emit |
| 原生先行 | Cordis prepend 是外层；守护先 await next。normal 有预算直接等待并返回 retry；always 下游先行且永不耗尽，守护跳过 |
| 真正耗尽 | 与当前 provider、完整已解析 policyKey 匹配的 `llmRetry` 投影计数达到 maxRetries。原生 code 不适用或 Retry-After 超本地 cap 的提前 next 不冒充耗尽 |
| 版本读取 | 真实 Loader + PluginPackages 的 baseUrl/packageOf，以及当前 Host 状态工具，均确认 0.2.1-rc.3 的受支持契约 |
| 原生观察 API | `observeSession(id, options)` 返回 SessionObservation，读取其 `projections.values`，用 `[Symbol.dispose]()` 释放，不激活会话 |
| 问题 API | answer 仅支持 continued/整批提交，来源固定 user-question-reply；通用问题没有风险字段。open 原始 waterfall 与 continued 晚答分别核实 |
| Goal API | Host goals.resume 技术可调用；模型 update_goal 要求直接人类授权。没有将 active/disarmed 或方法存在视为可跨重启恢复凭据 |

## 审查与回归

独立缺陷优先审查发现并修复：

1. 原生 SessionObservation 方法、数据和释放方式不匹配；真实 SessionQueryEngine 集成测试现可完成首次状态读取与配置。
2. store 关闭丢弃队列中已接受的停止/撤销；现在拒绝新写、排空已接收写入，并有阻塞持久写入回归。
3. Windows 同名 Run 值缺少所有权检查；现在查询并验证 REG_SZ 数据，拒绝外来值，删除前再次核对。
4. 旧 completed 守护缓存掩盖新 interrupted 轮次；现在用 seq 判断完成缓存新鲜度。
5. 存储 close 失败泄漏 OS lease；现在 finally 释放，重复 dispose 共享同一清理 Promise。
6. 同会话旧 poll 覆盖 configure 新开关；现在有 read 序号、mutation fence 和 revision 单调检查。负向对照在内存中移除防护时测试能捕获旧缺陷。

## 已知剩余风险与未覆盖项

- 无法 100% 区分 crash、强退、断电与未落盘 Stop；原生 idle cancel 没有独立持久事件。缺少可靠证据时只提示确认。
- 原生 JSON backend 的跨文件审计不是事务：主状态和短审计尾先持久化，完整审计表后写；后者失败会停用自动动作。不能据旧审计复活撤销的授权。Windows rename 缺少额外 write-through，真实断电 durability 未实测。
- OS lease 使用本机回环端口排他。端口被其他程序占用也会停用，需人工排查；不能在不同机器共享同一可写数据目录时提供分布式锁保证。
- 原始错误 body/headers/cause 可能被适配器丢弃。插件无法识别已丢失的永久性信息；对保留信息中的未知分类保持停止。
- 当前原生预算键属于 0.2.1-rc.3 实现细节，升级版本需要重新核实，版本未知时不自动接管。
- 第三方 waterfall listener 若不遵守 next/abort 契约，可能阻塞原生取消。守护不改变其行为或抢占未耗尽的原生策略。
- 未验证真实 Windows 环境、真实 macOS LaunchAgent 登录域启停、应用重启、断电、实际磁盘解锁/自动登录，以及当前 GUI 的完整视觉与键盘操作。
